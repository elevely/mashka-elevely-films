# Mashka & elevely Films

Личный киноклуб двух зрителей. В карточке сохраняются пять оценок каждого автора, два индивидуальных итога, общая оценка и заметки. Старые фильмы читаются из существующей таблицы `public.movies`. Дата под карточкой означает дату добавления.

## Запуск

Нужен Node.js 24. Команды запускаются **из корня репозитория**.

```sh
npm ci --ignore-scripts
npm run demo
```

Откройте http://localhost:4173. Зелёная полоса помечает изолированный стенд. Войдите с тестовыми данными, указанными в форме входа. Восемь вымышленных фильмов живут в памяти процесса. Стенд не использует сеть для поиска, не читает ключи Supabase и сбрасывается при остановке. Для настоящего подключения скопируйте `.env.example` в `.env`, заполните параметры и запустите `npm run dev`.

| Команда | Назначение |
| --- | --- |
| `npm test` | Проверка API, модели и настоящего HTTP-сервера на временном порту loopback |
| `npm run build` | Проверка синтаксиса, конфигурации маршрутов, подготовка статической сборки в dist/ |
| `npm run backup -- backups/before.json` | Приватный GET-экспорт всех доступных строк и колонок, включая неизвестные приложению |
| `npm run verify-backups -- backups/before.json backups/after.json` | Сравнение записей по ID и содержимому. Различия дают ненулевой код выхода |

## Коллекция и оценки

Поиск учитывает русское и оригинальное название, год, фильтр по жанру. Сортировка работает по дате, названию и оценкам каждого зрителя. В «Любим оба» попадают фильмы, которым оба поставили от 80 баллов. В «Мнения разошлись» разница составляет от 20 баллов. Вкладка «Наши вкусы» показывает персональные топы, средние по критериям и среднюю абсолютную разницу. Пропущенные оценки исключаются из среднего, нулевые учитываются.

Для нового фильма сохранена исходная формула. Индивидуальный результат равен сумме оценок с весами `1, 1, 1, 1, 1.5`, делённой на `5.5` и умноженной на `10`. Общий результат — округлённое среднее **двух неокруглённых** индивидуальных результатов. Для исторических записей интерфейс берёт готовые значения из БД. Загрузки и перезагрузки ничего в неё не записывают.

Владелец может добавить фильм через поиск или вручную и редактировать заметки. При неудаче текст остаётся в открытой форме. Совпавшие изменения из двух вкладок проверяются на сервере и атомарно в PostgreSQL. API разрешает добавление и обновление трёх полей заметок. Удаление фильмов и редактирование старых баллов отключены. Гость может скачать показанную коллекцию в JSON. После входа экспорт включает исходные колонки, доступные владельцу.

## Устройство проекта

- `public/` — статический интерфейс на ES Modules. Шаблоны экранируют динамический текст. `lib/model.js` используется также на сервере для расчёта новых оценок.
- `api/{movies,auth,search}.js` — точки входа Vercel. `server/handlers.mjs` проверяет метод, источник запроса, сессию, поля и размер JSON. `server/supabase.mjs` использует Supabase Auth и PostgREST через встроенный fetch с тайм-аутом.
- `docs/notes-function.sql` — отдельно устанавливаемая функция сравнения и сохранения заметок с правами вызывающего пользователя. Никакие SQL-файлы не запускаются при сборке или старте.
- `tests/` — синтетическая коллекция, API, HTTP, PostgreSQL и браузерные сценарии. GitHub Actions поднимает отдельный PostgreSQL и Chromium. Снимки экрана тестовых данных сохраняются в артефакте запуска.

## Vercel и доступ к Supabase

1. Выберите **Root Directory = корень репозитория**, Framework Preset = Other, Node.js = 24. Конфигурация задаёт `npm run build`, выход `dist/` и три функции из `api/`. Старые ссылки `/admin` и `/admin.html` открывают форму входа. Ветку production оставьте `main`.
2. Сначала используйте отдельный проект Supabase для Preview. Задайте `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `APP_ORIGIN` (точный origin с https, без завершающего слеша), `ENABLE_WRITES=false` и `RLS_VERIFIED=false`. Если preview имеет динамический адрес, назначьте фиксированный preview-домен или обновите APP_ORIGIN для этого адреса. Для поиска задайте новый серверный `KINOPOISK_API_KEY`. Без него доступно ручное добавление.
3. Создайте два аккаунта Supabase Auth в тестовом проекте, отключите публичную регистрацию, запишите их UUID через запятую в `ALLOWED_ADMIN_IDS`. Сервер проверяет токен через Auth и список UUID. Сессия хранится в HttpOnly cookie на срок до часа, в HTTPS используется Secure. По истечении срока требуется повторный вход.
4. Проверьте типы, ограничения и доступы через [инструкцию аудита](docs/security.md). Установите функцию заметок **в тестовом проекте** после сверки типов. Включите обе переменные записи только после проверки политик. Проверьте вход, создание фильма, изменение заметок, повторную загрузку и отказ в удалении на синтетических данных.
5. Для перехода на рабочую базу владелец отдельно согласует изменения политик и установку функции. Сначала сохраните полный экспорт и сопоставьте число строк с dashboard. Подключите production в режиме чтения и сравните экспорт до и после. Только после проверки и согласования укажите production origin, ключи и режим записи.

В веб-приложении используется только публичный ключ и токен вошедшего пользователя. Привилегированный ключ для Vercel не требуется. Для приватного экспорта командой backup локально задайте `SUPABASE_BACKUP_KEY` с заведомо полным доступом SELECT. Убедитесь, что считано ожидаемое число строк: RLS может возвращать доступное подмножество без ошибки. Команда читает данные дважды, проверяет хеш и создаёт новый файл с правами 0600. Храните копию вне публичных каталогов. Это экспорт коллекции, для полного восстановления проекта сохраните отдельно резервную копию PostgreSQL через Supabase. При наличии bigint/numeric за пределами точности JavaScript используйте штатный дамп PostgreSQL.

Исходная версия — коммит `8f21ca93983ef8c170ac8addea837f5fe757d879`. До слияния откат сводится к закрытию PR. При откате опубликованного интерфейса старый API вновь получит прежнее поведение; запреты на запись должны сохраняться на уровне БД.
