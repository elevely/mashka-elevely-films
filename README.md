# Mashka & elevely Films

Персональный киноклуб Машки и elevely: общая коллекция, пять критериев каждого зрителя, две независимые рецензии, совместный рейтинг и статистика вкусов. Источник данных — существующая таблица `public.movies` в Supabase. Загрузка страницы ничего в неё не записывает. Удаления фильмов в приложении нет.

## Быстро посмотреть результат без ключей

Установите Node.js 24. В Terminal:

```sh
cd /Users/elisei/mashka-films-rebuild
npm ci --ignore-scripts
npm run demo
```

Откройте [localhost:4173](http://localhost:4173). Если порт занят: `DEMO_PORT=4273 npm run demo`, затем [localhost:4273](http://localhost:4273).

**Только на этом изолированном стенде:**

| Зритель | Тестовая почта | Тестовый пароль |
| --- | --- | --- |
| elevely | `elevely@example.test` | `demo-only` |
| Машка | `mashka@example.test` | `demo-only` |

Зелёная полоса помечает вымышленные данные. Стенд не обращается к Supabase или Кинопоиску, не читает `.env`, хранит фильмы только в памяти и сбрасывается после остановки. Эти почты и пароль **не создают реальные аккаунты** и не работают на настоящем сайте. Чтобы остановить сервер, нажмите Ctrl+C.

## Как пользоваться

Нажмите **Войти**, введите почту и пароль своего реального аккаунта. В шапке появится **Машка** или **elevely**. Для выхода нажмите своё имя → **Выйти**.

Нажмите **Добавить фильм**, найдите его по названию или раскройте **Добавить вручную**. Поставьте пять своих оценок от 0 до 10 с шагом 0,5, напишите заметку и сохраните. Второй зритель входит в собственный аккаунт, находит этот же фильм в коллекции и нажимает **Моя рецензия**. Повторно добавлять фильм не нужно. Общий балл появится после второй оценки.

В существующем фильме кнопка **Моя рецензия** позволяет изменить только ваши критерии и заметку. **Только заметку** сохраняет текст даже без заполненных оценок. Флаг спойлеров общий для фильма. Ошибка сети оставляет черновик в форме. При конфликте между устройствами запись отклоняется: скопируйте черновик, закройте форму, обновите страницу и откройте рецензию заново. При смене аккаунта в другой вкладке сохранение старой формы отклоняется; войдите под её автором.

На сайте нет регистрации и восстановления пароля. Пароль меняется владельцем через управление Supabase Auth; настройка описана ниже. Сессия продлевается через HttpOnly cookies. Refresh cookie сохраняется до 30 дней с последнего продления, если её не удалил браузер и сессия не отозвана в Supabase. При окончательном истечении сессии войдите снова; несохранённую форму можно оставить в первой вкладке и войти **в тот же аккаунт** во второй.

Поиск учитывает русское и оригинальное название и год. Доступны жанры и сортировка по дате, названию, общему или личному баллу. «Любим оба» — оба результата от 80, «Мнения разошлись» — разница от 20. «Наши вкусы» показывает персональные топы и средние. Пока страница открыта без модального окна, коллекция обновляется раз в минуту и при возвращении на вкладку. В открытом черновике автоматическое обновление приостановлено; сервер всё равно проверяет конфликты.

## Формула и исторические данные

Веса пяти критериев: `1, 1, 1, 1, 1.5`. Индивидуальный итог: `round(взвешенная сумма / 5.5 × 10)`. Общий итог: округлённое среднее **двух неокруглённых** индивидуальных результатов. Нули учитываются; отсутствие оценки не считается нулём. При отсутствии второго набора общий итог пустой.

Старые итоги читаются из базы как есть, даже если они расходятся с формулой. Просмотр, сборка, экспорт, установка SQL и сохранение одной заметки не пересчитывают оценки. После явного изменения собственных критериев пересчитываются ваш итог и общий итог; сохранённый личный итог второго зрителя не меняется. Неизвестные старые колонки, даты и сведения о фильме сохраняются.

## Подключить настоящий Supabase локально

Сначала используйте **отдельный тестовый проект**, заполненный только вымышленными записями. Не включайте запись в рабочую базу до резервной копии, аудита и отдельного согласования.

1. Скопируйте `.env.example` в `.env`: `cp .env.example .env`. `.env` исключён из Git. Откройте файл в редакторе и заполните параметры из таблицы. Секреты не отправляйте в чат, GitHub, issues и screenshots.
2. В Supabase Dashboard → Project Settings / API найдите адрес проекта и **publishable key** (`sb_publishable_…`) либо прежний **anon key**. Приложение отклоняет `sb_secret_…` и JWT с ролью `service_role`.
3. В Authentication создайте два аккаунта по следующей инструкции и запишите их UUID.
4. В SQL Editor выполните только [аудит SELECT](docs/rls-audit.sql). Сверьте схему, типы, nullable-поля, политики, функции и триггеры по [инструкции безопасности](docs/security.md).
5. Подготовьте и проверьте [owner-writes.sql](docs/owner-writes.sql) в отдельной тестовой базе. Везде замените `REPLACE_ELEVELY_UUID` и `REPLACE_MASHKA_UUID` на соответствующие UUID. Файл меняет права/политики/функции/триггер, но не обновляет строки. Не применяйте его к production без резервной копии и согласования.
6. Только после проверки прямого доступа обоих владельцев, анонима и постороннего UUID включите `ENABLE_WRITES=true` и `RLS_VERIFIED=true`. Это ручные подтверждения проверки, а не автоматический аудит.
7. Запустите `npm run dev` и откройте адрес из Terminal. Без настроенного Supabase появится понятная ошибка подключения; демонстрационные фильмы не подставляются.

| Переменная | Что указать |
| --- | --- |
| `SUPABASE_URL` | `https://<ваш-проект>.supabase.co` |
| `SUPABASE_ANON_KEY` | Publishable / anon ключ. Сервер использует токен вошедшего пользователя для записи |
| `ELEVELY_USER_ID` | UUID реального аккаунта elevely из Supabase Auth |
| `MASHKA_USER_ID` | Другой UUID реального аккаунта Машки |
| `APP_ORIGIN` | Локально `http://localhost:4173`; на production точный `https://<имя>.vercel.app`, без `/` в конце |
| `KINOPOISK_API_KEY` | Новый серверный ключ Кинопоиска. Без него доступно ручное добавление |
| `ENABLE_WRITES`, `RLS_VERIFIED` | Сначала оба `false`; `true` только после проверки и согласования |
| `SUPABASE_BACKUP_KEY` | Только локально для полного приватного экспорта; на Vercel не добавлять |
| `PORT` | Локальный порт настоящего сервера, по умолчанию 4173 |

`ALLOWED_ADMIN_IDS` из предыдущей версии больше не выбирает владельцев: нужны два отдельных UUID. Публичная регистрация в Auth должна быть выключена. Роли не берутся из изменяемого пользователем metadata.

## Создать оба настоящих аккаунта и задать пароли

1. Откройте **нужный** проект Supabase → Authentication → Users. Если аккаунты уже существуют, используйте их: не удаляйте и не пересоздавайте пользователей.
2. Для отсутствующего пользователя нажмите **Add user → Create new user**, укажите его настоящую почту и отдельный длинный пароль. Подтвердите почту через **Auto Confirm User**, если эта опция доступна. Повторите для второго зрителя.
3. Скопируйте **User UID** elevely в `ELEVELY_USER_ID`, Машки — в `MASHKA_USER_ID`. Те же UUID укажите в подготовленном SQL. Имена профилей в Supabase не определяют владельца оценок.
4. В Authentication → Sign In / Providers → Email убедитесь, что вход по почте/паролю включён. Выключите **Allow new users to sign up**. Создание пользователей администратором остаётся доступным.
5. Для уже созданного аккаунта задайте новый пароль через доступное действие управления пользователем в Dashboard. Если интерфейс предоставляет только отправку reset-ссылки, используйте официальный [Admin API updateUserById](https://supabase.com/docs/reference/javascript/auth-admin-updateuserbyid) в доверенной серверной среде с полем `password`; привилегированный ключ нужен только этой административной операции, не приложению. Не используйте reset-ссылку на этот сайт: отдельной страницы смены пароля в нём нет.
6. Перезапустите локальный сервер или сделайте новое Preview-развёртывание после изменения окружения. Нажмите **Войти**, используйте настоящую почту и установленный вами пароль. Правильное имя в шапке подтверждает сопоставление. Проверьте оба аккаунта в разных браузерах.

Пароли здесь не заданы: доступа к вашему Supabase нет. Тестовый пароль `demo-only` не используйте для реальных аккаунтов.

## Бесплатная публикация через Vercel

Выбран Vercel Hobby: он сохраняет три серверных API и подходит для персонального проекта. [Hobby бесплатен в пределах лимитов](https://vercel.com/docs/plans/hobby). GitHub Pages [публикует статические файлы](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), а для текущего API понадобился бы отдельный backend. Другую платформу подключать не требуется.

Сейчас подготовлены исходники и проверки; облачный Preview и production **не создавались**. Не сливайте ветку с `main` до проверки и отдельного разрешения на production.

1. В Vercel выберите личный Hobby, не Pro trial и не платные дополнения. Подключите GitHub-репозиторий `elevely/mashka-elevely-films`. Для уже подключённого проекта откройте его настройки.
2. **Root Directory** — корень репозитория, поле пустое / `.`. **Framework Preset: Other**, **Node.js: 24.x**, **Build Command: npm run build**, **Output Directory: dist**, **Install Command: npm ci --ignore-scripts**. `npm run build` запускает `node scripts/build.mjs`; он не вызывает Vercel и не запускает сам себя.
3. **Production Branch: main**. До разрешения не нажимайте Deploy для `main`, Promote to Production и не запускайте `vercel --prod`. Если подключение нового проекта предлагает немедленно развернуть `main`, отложите этот шаг; для проверки используйте Preview ветки.
4. В **Environment Variables → Preview** добавьте параметры **отдельного тестового Supabase**, оба UUID и новый ключ Кинопоиска. Сначала оставьте запись выключенной. `APP_ORIGIN` для Preview можно не задавать: сервер возьмёт точный origin из доверенного `VERCEL_URL`. Если используете постоянный preview alias, задайте его origin явно. Настройки Production и Preview разделяйте; Preview не должен писать в рабочую базу.
5. После публикации рабочей ветки на GitHub создайте её **Preview**. В CLI обычный `vercel` создаёт Preview; не используйте `--prod`. Откройте выданную HTTPS-ссылку. Если включена Vercel Deployment Protection, доступ к preview сначала требует входа в Vercel — это отдельный вход от аккаунтов киноклуба.
6. На синтетических данных пройдите: вход elevely → поиск → добавление → сохранение → выход → повторный вход; затем вход Машки на другом устройстве → своя оценка → общий итог → сохранение после перезагрузки. Проверьте запрет прямой чужой записи и конфликт двух форм.
7. Для рабочей базы: сначала полный backup, аудит и согласование изменения прав. После согласованной установки защиты сравните экспорт до/после. Настройте **Production** с настоящими ключами, UUID и точным `APP_ORIGIN`. Не включайте запись до проверки RLS. Только после отдельного разрешения на публикацию слейте проверенную ветку в `main` и запустите production.
8. Постоянный бесплатный адрес вида `https://<имя>.vercel.app` работает без MacBook. Vercel предоставляет HTTPS. Сохраняйте Git integration: после первой разрешённой публикации последующие изменения в `main` автоматически обновляют сайт. Рекомендуется требовать успешный QA и ревью перед merge.

При смене окружения требуется новое развёртывание. `api/*.js` развёртываются как Node Functions, `dist/` содержит только frontend. `vercel.json` задаёт 60 секунд на функцию и перенаправляет старые `/admin` и `/admin.html` на форму входа. Сборка не обращается к базе.

## Резервные копии и восстановление

Git хранит код, **не данные Supabase**. Кнопка **Экспорт** у гостя скачивает только показанную коллекцию; после входа — все доступные исходные колонки. RLS может скрывать строки, поэтому такой экспорт сам по себе не доказывает полноту.

Перед изменениями production:

1. В Dashboard зафиксируйте ожидаемое количество фильмов. Сохраните определения схемы, grants, политик, функций и триггеров. Не размещайте их с личными данными в публичном репозитории.
2. Локально в `.env` временно задайте `SUPABASE_BACKUP_KEY` с подтверждённым полным SELECT. Выполните `npm run backup -- backups/before.json`. Скрипт делает только GET, читает коллекцию дважды, сверяет хеш, отказывается перезаписать файл и создаёт его с правами 0600. Сверьте rowCount с Dashboard. Уберите backup key из `.env` после экспорта.
3. Отдельно сделайте PostgreSQL-дамп штатным средством Supabase CLI / `pg_dump` по инструкции [резервного копирования Supabase](https://supabase.com/docs/guides/platform/backups). JSON коллекции не включает Auth, роли, политики и все объекты проекта. Для bigint/numeric за пределами точности JavaScript используйте дамп, а не JSON. Надёжность восстановления нужно проверять на отдельном проекте.
4. После изменения схемы/прав в спокойный момент сделайте `backups/after.json` и запустите `npm run verify-backups -- backups/before.json backups/after.json`. Ожидается `identical:true`, `missing:0`, `changed:0`, `added:0`. Несовпадение требует расследования. Не допускайте пользовательскую запись между снимками, если ожидаете полного равенства.
5. Скопируйте резервные файлы в защищённое место вне проекта и храните несколько датированных версий.

При проблемах отключите `ENABLE_WRITES`, создайте новое развёртывание, сохраните текущий снимок и логи без cookies/паролей. Восстановите дамп сначала в **новый** тестовый проект, проверьте число строк, оценки, заметки и вход. Переключение на восстановленную базу и любые перезаписи рабочей базы требуют отдельного согласования. Автоматического destructive restore-скрипта в проекте нет.

Откат интерфейса делается через предыдущий проверенный Vercel deployment. Не удаляйте защитный триггер при откате: он сохраняет права владельцев и при старом API. Политики и grants откатывайте только к сохранённому безопасному состоянию после согласования. Если новая версия не работает, сначала используйте режим чтения.

## Проверки и структура

| Команда | Назначение |
| --- | --- |
| `npm test` | Unit, обработчики API и настоящий HTTP на временном loopback-порту |
| `npm run build` | Проверка синтаксиса, маршрутов и статическая сборка |
| `npm run test:browser` | Chromium E2E; запускает собственный свежий синтетический сервер |
| `npm run test:db` | Политики/триггер/RPC на **пустой одноразовой** PostgreSQL БД с именем `films_test` или `films_test_*` |
| `npm audit --omit=dev` | Проверка зависимостей приложения |

Для браузерных тестов установите Playwright отдельно: `npm install --prefix /tmp/films-browser --no-audit --no-fund playwright@1.56.1`, затем `/tmp/films-browser/node_modules/.bin/playwright install chromium` и `PLAYWRIGHT_MODULE=/tmp/films-browser/node_modules/playwright npm run test:browser`. Скриншоты — в исключённом из Git `test-results/`.

Для PostgreSQL-теста задайте `PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE` своей одноразовой базы; нужны `psql` и права на создание тестовых ролей/таблиц. Скрипт не загружает `.env`. Запускать на рабочей базе запрещено. GitHub Actions создаёт PostgreSQL 16 и Chromium отдельно; локальная проверка выполнена на PostgreSQL 18. GitHub Actions после изменений в этой ветке удалённо ещё не запускался.

- `public/` — интерфейс без runtime-зависимостей, динамический текст экранируется.
- `server/` — валидация, роли аккаунтов, Supabase Auth / REST через серверный fetch, HTTP-стенд.
- `api/` — три входа Vercel: auth, movies, search.
- `docs/owner-writes.sql` — проверяемая отдельно защита личных рецензий. SQL не запускается приложением, сборкой или деплоем.
- `tests/` — вымышленные данные, API/HTTP, браузер и PostgreSQL.
- [Результаты и ограничения проверки](docs/verification.md), [безопасность](docs/security.md).
