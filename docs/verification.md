## Сохранность настоящих данных

Настоящая база не подключалась: ни SELECT её строк, ни INSERT/UPDATE/DELETE не выполнялись. Production backup не создан, поскольку нет ключей; копия кода и успешные fixture-тесты его не заменяют. Подготовленный `docs/owner-writes.sql` применялся только к синтетическому PostgreSQL. В нём нет UPDATE существующих строк при установке. Его установка в рабочую базу требует аудита схемы, backup и разрешения владельца. Сборка, запуск и deployment не запускают SQL автоматически.

## Вход и выпуск

Локальный стенд: `npm run demo` (или `DEMO_PORT=4273 npm run demo`). В нём доступны `elevely@example.test` и `mashka@example.test`, пароль `demo-only`. Это только вымышленные аккаунты.

Настоящие аккаунты создаются/проверяются в Supabase Authentication, отдельные пароли задаёт владелец. Два UUID записываются в `ELEVELY_USER_ID` / `MASHKA_USER_ID` и согласованный SQL. Полная инструкция и действия при сбросе пароля — в README, раздел «Создать оба настоящих аккаунта и задать пароли».

Перед публикацией необходимо:

1. Отозвать ранее опубликованный ключ Кинопоиска и настроить новый только на сервере.
2. Настроить отдельный тестовый Supabase, два аккаунта и UUID. Проверить реальную схему и допустимость отсутствующей второй оценки.
3. Проверить подготовленный SQL и прямой доступ в staging; затем пройти реальный пользовательский сценарий с Кинопоиском и Auth.
4. Подключить Vercel Hobby, переменные Preview и создать HTTPS Preview рабочей ветки. Проверить облачную сборку, cookies, API и мобильный браузер на устройстве.
5. Сделать полный production backup, проверить восстановление в отдельный проект; согласовать изменения политик/триггера, применить и сравнить экспорты до/после.
6. Отдельно согласовать production-выпуск, настроить Production env и только после этого объединить с main. Git integration обеспечит дальнейшие обновления main.

Постоянной тестовой интернет-ссылки пока нет. Проект не выдаётся за проверенный production-продукт: осталось подтвердить совместимость с настоящей базой и работу внешних сервисов. Коллекция по прежней модели доступна гостям вместе с заметками, если anon RLS это разрешает. Мгновенный отзыв ранее скопированных access JWT и мгновенный realtime не реализованы; обычное продление/выход и периодическая синхронизация описаны в README.
